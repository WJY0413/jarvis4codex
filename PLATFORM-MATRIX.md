# 0.2.6 platform integration boundaries

| Area | Linux dot.1 decision | Evidence and limit |
|---|---|---|
| Exact-terminal fallback | Preserve accepted Linux implementation | Native launcher, Hold owner and monitor byte-identical to accepted core |
| Alias cancellation / request replay / owned dispatch | Merge Task A revision 1 | Three source files exactly match reviewed handoff after-hashes |
| Model / effort / service tier | Preserve frozen explicit Linux policy | Runtime constraints, model and effort must be declared in deployment; no general project-config auto-selection claim |
| Per-thread cwd selection | Windows automatic config/read feature not adapted | Linux thread creation still uses allowed project path; no Windows selection context override introduced |
| 128-entry cwd LRU | Not introduced | Current Linux has no thread-cwd cache requiring eviction or lifecycle cleanup |
| Loopback HTTP listener recovery | Integrate shared audited function | Entire hunk exactly matched after CRLF normalization; stdio unchanged; bounded listener rebuild with no tool replay |
| Original full Jarvistest | Required on frozen Linux identity | One independent TEST packet, capacity 2, original P0–P7 inputs/assertions, no production state |

These editions share core version 0.2.6 but have deliberately different adapter capability boundaries. Linux formal stdio verification does not imply a real-platform HTTP fault was reproduced.
